# AutoAdv 開発原則

1. 完成後の責務・状態所有・イベント順を先に確定する。`Controller`以外に進行権限を与えない。
2. LunaTranslatorとゲーム、Windows音声/画面、Irodori、入力ドライバは交換可能なAdapterとする。
3. 原文受信・音声VAD・無音時間の単体観測から台詞境界や終了を捏造しない。未知は停止させる。
4. `session_id`、`line_epoch`、`cancel_token`、monotonic timestampを非同期イベントに付与する。
5. 正準仕様の不変条件・状態遷移・責務境界をテストし、実機未検証をfixture成立で代替しない。
6. 通常開発の対象branchは`develop`。`main`は明示承認まで不変更。通常のpublishは現行AutoAdvの標準Publish Gatewayを使用し、最新Fast CIのsource-snapshotから復元する。
7. 局所修正で旧経路を残さず、責務を縦断する共通契約へ統合する。
8. 旧テストは成立済みという理由で保持しない。各アサーションを完成時仕様で必要な不変条件・状態遷移・Application契約に照らしてゼロベース評価する。新仕様に表面的に適合させた書換え、テスト件数・検出力維持を目的とする新旧経路の残置、テスト合格だけを目的とする実装変更を禁止する。
9. テスト失敗時は最初にアサーションの必要性・仕様との一致・他テストとの重複を確認する。無効なテストと、その維持だけのために存在する実装は撤去する。有効な契約が失敗した場合にのみ、本体の原因をDomainからUIまで追跡して修正する。削除・統合の判断は変更対象全域で行い、代表例の修正で監査完了としない。

10. ゲーム全体の状態や選択肢不存在を観測・証明することを完成条件にしない。HOOK本文＋native/ASR＋選択的Irodori TTSの同期に実用上必要な観測だけを実装し、汎用画面マーカー、状態判定Provider、独立ACK系統を常設しない。
