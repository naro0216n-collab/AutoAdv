# AutoAdv — 製品仕様

## 1. 目的

AutoAdvは、個人利用のWindows GUIアプリとして、次の一連の操作を実現する。

1. **LunaHookからゲームの台詞を取得する。** ゲームに適したHOOKを探して選び、作品別に保存し、次回起動時にも使えるようにする。
2. **必要な台詞をIrodori TTSで補完する。** 原文から話者・本文・読みを求め、話者と作品ごとの設定に従って音声を使い分ける。
3. **ゲームの音声収録状況にかかわらず通常の会話を自動で進める。** 既存音声・TTS・閲覧時間を適切に扱い、プレイヤーが許可した間、台詞の提示に合わせて送り操作を行う。

LunaTranslatorを別途起動して設定を重複管理することなく、複数の作品とプロファイルを継続利用できる。完成の判定は、これらが実際のゲームと日常的なGUI操作で一続きに使えることで行う。

## 2. 通常の操作

### 初回の共通設定

- GUIで既存のIrodori-TTS-Serverフォルダを指定する。既存サーバーへの接続を優先し、必要なら指定された環境をAutoAdv起動時に自動起動する。
- 使用可能なVoice IDを取得し、試聴できる。サーバー・Voiceの状態と問題をGUIで確認できる。
- 音声取得・ASRなどは、選択した動作に必要な場合に設定する。音声監視を使わないTTS運用にASRモデルや音声捕捉環境の準備を必須としない。
- インストール・モデル取得・既存音声素材の加工は利用者が明示的に行う。AutoAdvは外部のインストール環境を勝手に変更しない。

### 作品の設定と使用

1. ゲームを選択・登録し、必要ならAutoAdvから起動する。実行中のゲームは識別情報から候補を提示する。候補が重複する場合は利用者が選ぶ。
2. HOOKを探索し、取得した原文をプレビューして選択する。HOOKコード、取得補正、関連する出力を作品のプロファイルへ保存する。
3. 話者・本文の分離、読み替え、話者別Voice、TTSを使用する台詞と既存音声の扱いを設定する。適用後の文と試聴結果を確認できる。
4. 監視を開始すると本文と適用設定、音声の処理状況が確認できる。自動送りは利用者が別途明示的に許可する。
5. 進行中も一時停止・手動操作・再許可ができる。対象のゲームやプロファイルを切り替えたときは、前の処理が残らない。

接続状態、取得原文、話者・本文、適用Voice、音声処理、進行の許可と停止理由など操作判断に必要な情報は、無効時も状態を示して所定位置に表示する。表示を隠したり入れ替えたりすることを簡素化の手段としない。取得・音声・入力処理でGUIをブロックしない。設定変更は適用時点を明確にし、進行中の台詞を予期せず置き換えない。

## 3. ゲーム台詞の取得

### LunaHook

標準の本文取得源はLunaHookとする。LunaTranslatorが培ってきたエンジン・エミュレーター対応、HOOK探索・追加・選択・復元、取得品質処理を活用する。Native/Hostと関連Python側の有用な資産を、上流版との整合と更新追随の負担を考慮して統合する。

Lunaの採用版は公式リリース`v12.1.2.12`（commit `51884b6c88cba8c42e98ce3e43c4f408017082a1`）を基点とし、対応する上流ソースと公式配布Native実行資産をAutoAdvで固定管理する。通常の起動・テスト・CIでは上流を取得・再ビルドしない。更新は利用者が明示的に選択した採用時だけ、版・配布物ハッシュ・ライセンスと差分を検証してまとめて取り込む。

本文のまとめ方は上流LunaHostのflush遅延・コードページ・最大バッファに委ね、設定をゲーム別に保存する。AutoAdvはflush済み通知に二度目の文字列バッファ確定や逐次増加の独自推測を加えない。flush通知は上流の出力単位であり、ゲーム内での意味上の台詞境界を必ずしも保証しない。連続する同文が別台詞かどうかは、選択した出力・入力後の状態と作品別の明示規則で扱う。

複数HOOKを選択した場合は、採用版Lunaの`Luna_SyncThread`で選択スレッドのflushタイミングを同期し、Luna Python側の複数選択出力収集と同様に、flush済みの出力を短時間（上限100ms）集約する。これはNativeの文字列flushとは別の、複数出力の対応付けであり、セリフを再分割する第二の取得機構ではない。本文HOOKと話者HOOKの受信順に依存させず、登録済み役割・関連付けを用いる。複数の本文や話者が同一集約に入り対応が不明なら自動的に結合・推測せず、送りの許可を停止して表示する。同期・収集を必要としない単一HOOKには追加の集約遅延を課さない。

- 候補HOOKのコード、対象プロセス、スレッド/contextなどの識別情報と、受信した原文を関連付けて表示する。手動HOOK追加、保存HOOKの再接続、取得補正を扱う。
- 本文と話者などが複数のHOOKに分かれて出力される作品では、利用者が出力の役割・対応・優先順位を設定できる。対応関係の不明な出力は別の候補として扱う。
- 通知ごとに、取得元、作品・プロファイル、接続世代、受信順序、時刻、利用可能なHOOK情報を保持する。上流処理後の文字列とゲーム内部の生バイトを区別する。
- 文字列の逐次増加、同文の反復、別台詞の同文、空通知、別HOOKの混信を、ゲームの取得特性と設定に従って処理する。更新通知一回を常に台詞一個とみなさず、同文であることだけで別台詞の可能性を排除しない。

### 任意OCR

HOOKで取得できない作品には、利用者が明示的に選択するOCR取得を用意する。初期対応は既にインストール済みのTesseract CLIとし、エンジン・言語・画面領域を作品ごとに保存する。OCR本文は同じ解釈・音声経路へ渡す。OCRの文字誤認や表示変化を踏まえ、取得の安定性と会話送りの設定は実用できる範囲で扱う。HOOKで利用する作品にはOCRの設定を要求しない。

## 4. UtteranceとTTS利用設定

LunaHostの選択済みflush出力から、話者、表示本文、読み上げ文、原音照合文、TTS使用有無、Voiceを一つのUtteranceに確定する。本文分離、複数HOOK集約、読み規則、ルビ、話者別Voiceおよび作品別設定は同じ正本を使う。表示・ASR・TTSの補正を混同せず、元の本文は表示・待機計数の根拠として保持する。

- 作品既定の `default_tts` と話者別 `speaker_tts` は真偽値。話者設定が優先する。Voice IDが登録されているだけではTTS使用を示さない。
- TTS使用と進行方式は独立する。ASR、VAD、音声未検出、経過時間がTTS使用の決定を変更することはない。
- TTS利用台詞はIrodoriに合成・実再生を依頼し、成功・失敗・取消を区別する。ゲーム原音と重なる可能性は作品の音声設定に依存するため、ASR抑制をゲーム音声ミュートと同一視しない。
- TTSを使わない台詞では原音を再生するかどうかをAutoAdvがゲームに強制しない。非使用はあくまでAutoAdvのTTS不使用である。

## 5. 自動進行の2モードと提示完了

ユーザーが選ぶ進行方式は **「文字のみ判断」（`text`）／「音声判断」（`audio`）の2つだけ**。どちらの方式でも自動送信は別途明示的な許可を要する。表示本文・音声・台詞ごとの設定は受理時に凍結し、設定変更は次のUtteranceから適用する。

| 進行方式 | TTSを使用するUtterance | TTSを使用しないUtterance |
|---|---|---|
| 文字のみ判断 | 表示本文から計算する閲覧時間と、Irodoriの**実デバイス再生終了**の両方を待つ。原音ASRを実行しない | 計算した閲覧時間で提示完了。原音を途中で送る可能性があり、原音ASRを実行しない |
| 音声判断 | Irodoriの**実デバイス再生終了**で提示完了。原音ASRは不要 | 対応が確認された原音の再生終了を優先。確証が得られない場合はフォールバックの明示設定に従う |

音声判断かつTTS非使用のときのみProcess LoopbackからPCMとASR/VADによる観測を台詞に接続する。ASRの誤字、短文、仮名漢字差、囁き、泣き声・叫び声、同文の別発話、BGM/SEの重なりは、不存在・対応・再生終了を機械的に断定できない。Process Loopbackのheartbeatはhelperの生存通知であり、原音不存在または終了の証拠ではない。PCM不着とデバイス故障を混同しない。VADだけで対応台詞の発話と断定しない（音声だけに分離された作品の明示的なVAD専用設定を除く）。

音声判断内に限り、**「音声判定が不確かなとき、文字数待機時間で進む」**という1個のON/OFF設定を用意する。既定はOFF、共通設定・作品上書きが可能で、現在の適用値をGUIへ表示する。

- 対象は**TTS非使用の音声判断台詞のみ**。ONのときも原音終了を確認できた場合はそれを優先する。
- 受理時から文字のみ判断と**同じ文字数時間**を計測し、期限に原音の終了・対応が不確実かつ対応する原音の**継続が肯定的に確認されていない**場合に提示完了を認める。まだ原音が明確に再生中なら期限後も待つ。
- ONで期限に送るのは**「音声判定不確実：文字数時間で提示完了」**であり、原音が存在しない・終了したと認定したことにはならない。遅発原音・認識失敗で途中送りのリスクが残ることをGUIで示す。
- OFFの場合は根拠不足の時間送りをせず、停止・手動引継ぎとする。TTSの再生終了条件はON/OFFに影響されない。

## 6. 記号除外の文字数と自動送り権限

表示本文から日本語文字・アルファベット・数字等Unicode Letter/Numberを計数し、句読点・括弧・絵文字・空白・改行・単独結合記号を除く。長音「ー」は日本語の読みの一部として数える。ルビで元漢字と読みを二重に数えず、話者・読上げ辞書展開による増分を加算しない。

`character_count = count(display_body)`、`text_wait_ms = max(reading_ms, character_count × per_character_wait_ms)`。`reading_ms`は正の最低表示時間、`per_character_wait_ms`は正の1文字時間（ミリ秒）。どちらもGUIで調整・保存し、共通・作品別設定を継承できる。文字0個でも最低時間が働く。例：`「おはよう！」`は4、`「……」`は0。GUIは現在の計数と確定時間を示す。これは原音時間の推定精度を保証しない。

一台詞の提示完了には文字時間、TTS実再生終了、原音終了、明示された不確実時フォールバックの**互いに異なる理由**を持たせる。同じControllerがトークン・完了状態・送信履歴を所有する。GUI、TTS、NativeAudio、OCR、HOOKはControllerへ事実だけを報告し、個別にゲーム入力を送らない。

Controllerは入力前に明示許可、フォーカス、入力対象、セッション・Utterance token、TTS再生状態、手動停止、送信済みを確認する。一台詞一回の入力後は次のHOOKを待ち、所定の上限で手動引継ぎする。旧セッションのTTS通知や時間イベントは現行台詞を完成させない。失敗した音声再生を成功と扱わない。取得・TTSは自動送り許可なしでも使える。

## 7. 共通設定・作品・保存・GUI

AutoAdvは共通設定、作品プロファイル、セッションをそれぞれの役割で一元管理する。共通設定と作品別プロファイルには2モード、フォールバックON/OFF、TTS既定、Voice、最低表示時間、1文字時間、送りキー、次HOOK上限、音声・ASR環境を持つ。話者別TTS使用有無とVoiceはプロファイルに持つ。HOOK、任意OCR、取得補正、本文・読み・話者規則は作品別に保存し、PID/HWND・再生状態・音声活動はセッションだけが所有する。

GUIは進行2モード、フォールバック、最低時間、1文字時間、計数と確定時間、許可・停止・送信・完了理由を常時確認できる。TTS利用設定と進行設定を別群に表示する。関連しない状態表示や設定を無効時に隠したり位置を入れ替えたりしない。音声認識の未準備は文字のみ判断やTTS利用の必須条件ではない。

旧`settings-v3.json`は原本を保持し、非等価な旧`native/tts/auto/reading`を進行2モードへ機械変換しない。明示的にTTS指定済みの話者Voice、HOOK、本文規則、閲覧時間等の資産を取り込み、意味が不明な値と`reading_ms=0`の変更はGUIで確認を求める。ユーザー承認後は新設定`settings-v4.json`へ保存し、実行時に旧経路を並走させない。

## 8. 実装・運用条件

LunaHook Native/Hostをゲーム処理と分離して管理し、x86/x64、ABI、実HOOK出力、IPC切断と再接続を確認する。上流の採用版と取り込み手順を記録し、関連するNative・Host・Python資産の版を整合させる。権限や競合等の問題は利用者へ通知し、他アプリのプロセス・環境を勝手に終了・変更しない。Luna由来コードと依存物について必要なライセンス・権利表示に対応する。

入力と音声処理に必要な状態所有、イベントの適用順、ゲーム・プロファイル切替時の失効を一貫した構造にする。Domainから保存・Application・GUIまで同じ設定と状態が使われるよう接続する。

## 9. 受入条件

| 実利用・検証 | 成立すべき結果 |
|---|---|
| HOOK探索・選択・保存と複数選択出力 | Lunaのflushと選択HOOKの対応から一意な台詞・話者を得られ、曖昧な場合には入力を停止する |
| TTS利用と非使用の話者混在 | 話者別TTS使用の決定は2モードと独立し、TTS中に原音ASRを開始しない |
| 文字のみ判断 | 記号除外・ルビ計数・最低時間と設定された1文字時間で送り、TTS使用時には実再生終了も待つ |
| 音声判断・TTS使用 | ASRを使わずTTSの実再生終了で提示完了する |
| 音声判断・非TTS | 対応づいた原音終了を優先し、不確実時は明示フォールバックON/OFFの結果とその理由が一致する |
| 原音未検出・遅延・非言語・BGM | PCM/ASR/VADで確証を捏造せず、実測されたリスク・保留・途中送りを区別する |
| 連続送信、同文別台詞、セッション切替 | 一台詞一入力、旧Token失効、フォーカス・手動停止・次HOOK待機を満たす |
| 共通・作品設定と旧設定の取込み | 設定反映とGUI表示が一致し、旧ファイルを残して不明項目を利用者確認のうえ移行する |
| 実ゲーム検収 | Windows上の選択HOOK→ASR/TTS/文字判断→実入力→次HOOKを検証し、未実施を未検収として報告する |

ユニット・時系列・GUI・Persistence・Fast CI・実モデル・実ゲームの証拠を区別する。CER/RTFは補助指標で、モデル全音声一括認識を時系列会話送りの成功と同一視しない。fixture作者の分類や一定件数の保留だけを受入条件にしない。
