# AutoAdv 統合改修指示書

**Luna公開WebSocketへの一本化／AutoAdvによる本文分離・読み置換・選択的TTS／PySide6 GUI／Irodori Serverフォルダ指定後の自動起動・Voice ID取得／不要な旧経路の撤去**

改訂日：2026年10月20日
対象：`naro0216n-collab/AutoAdv`、通常開発ブランチ`develop`
位置付け：既存の統合実装指示書に対するユーザー指定の設計改訂。本書に定義する変更を`docs/integration-spec.md`等の正準文書へ反映した上で実装する。`docs/README.md`と`docs/development-principles.md`を作業開始時に確認する。コード・テスト・fixtureの現状や、従来の機能分類を新しい完成条件より優先しない。

## 1. 目的・判断基準

AutoAdvを、**LunaTranslatorが取得した原文に合わせてゲーム本来の音声を待ち、必要な話者だけをIrodori-TTSで読み上げ、それ以外の無音台詞は適切な閲覧時間を確保して自動進行させるWindows GUIアプリ**とする。選択肢など人の判断が必要な場面では止まり、ユーザーが選択を終えたら、条件が確認できた通常台詞から自動進行を再開する。

利用者の通常操作は、LunaでHOOKを選択し、AutoAdvで作品・話者・読み置換を設定し、**Irodori-TTS-Serverのフォルダを一度指定すること**に集約する。以後AutoAdvの起動時には、設定済みIrodoriへ自動接続し、必要なら既存環境から自動起動する。`voices`のVoice IDを取得し、話者割当てに表示する。Irodoriを毎回手動起動させない。

**設計判断の順序は「実際の利用目的 → 必要な動作と情報 → 実装」。** Domain分割、State数、DTOの純粋さ、従来の受入項目数、既存コード・テスト維持を独立した目的としない。同じ解析を繰り返さない、設定に矛盾を持ち込まない、安全停止できる等の具体的な利点がある場合だけ内部境界を設ける。不要な機能の撤去は、利用価値と新しい完成条件から決める。

### 完成時の通常経路

```text
対象ゲーム ──HOOK出力──> LunaTranslator
                              ├─ HOOK探索・選択・順序・結合
                              └─ 取得品質向けゲーム別前処理
                                       │
                              /api/ws/text/origin
                                       │
                                       ▼
                   AutoAdv（PySide6 GUI + 実行サービス）
                       ├─ Utterance：原文・話者・本文・
                       │    TTS文・ASR文・選択voice等を共通保持
                       ├─ 作品別の本文分離・読み置換・Voice割当て
                       ├─ nativeゲーム音声のProcess Loopback＋VAD/ASR照合
                       ├─ Irodoriの自動起動／Voice ID取得／TTS再生
                       ├─ 画面の進行許可・禁止・遷移確認
                       └─ 単一Controllerによる1回の入力とACK確認
                                       │
                          通常台詞だけゲームを進める

       手動選択が必要 → 自動入力を止める → ユーザーが選択
                                    → 新しい通常台詞と許可条件を確認
                                    → 自動進行へ復帰
```

ゲーム本来のAutoとLunaの`ttsautoforward`をAutoAdvと並行した入力主体にしない。Irodoriの起動成功はゲームへの自動入力許可を意味しない。初期状態では自動進行を許可しない。

**対象外**：参照音声のエンコード・変換、`prepare_irodori_voices.py`や`old/`隔離の管理、低遅延化・SSE最適化・モデルチューニング、HOOK選択UIのAutoAdvでの複製。これらを「見落とし」や実装完了の前提条件として付け加えない。

## 2. 残す機能・撤去する機能

| 機能・概念 | 今回の扱い | 理由 |
|---|---|---|
| **`Utterance`（原文・話者・本文・TTS/ASR文・Voice等の共通データ）** | **維持** | GUIプレビュー・TTS・ASR・診断で同じ結果を使える利便性がある。異なる属性を含むことだけを理由に分割しない |
| LunaでのHOOK探索・選択・複数HOOK結合 | 維持・Lunaへ委任 | 既存の利用可能な機能であり、AutoAdvで再実装する必要がない |
| AutoAdvの本文分離・読み置換・話者別TTS割当て | 強化 | TTSをAutoAdvで管理するためユーザーが設定・確認できる必要がある |
| Luna本体へのAutoAdvパッチ・UDP候補受信 | 撤去 | 公開WebSocketへ一本化し、Luna内部実装依存をなくす |
| AutoAdvの本文OCR・OCR文字列一致 | 撤去 | 原文取得はLunaに委任。文字列を二重取得しない |
| 作品別の最小限の画面判定 | 維持 | 選択肢停止・入力前の肯定的許可・遷移確認に必要 |
| `CHOICE`、`MAP`、`MENU`等を網羅するための独立認識器・六種必須マーカー | 撤去 | 欲しい情報は「入力可能／入力禁止／不明」とその根拠であり画面分類表の網羅ではない |
| 空台詞の取得不能イベント復元、同文連続の完全復元 | **通常完成条件から除外** | 公開WSに現れない情報を一般に再構成できない。観測できる境界のみ扱い、未知なら送らない |
| ゲーム内部Voice Metadata取得・署名Adapterの常設 | 撤去 | 標準経路では不要。ゲーム固有の実際に使える取得手段が明らかになった場合のみ個別判断 |
| Irodori独立のモデルReady管理、全Voice合成probe | 撤去 | 起動・ID取得・利用時の成否判定に必要ない管理の複雑化を避ける |
| Irodoriフォルダ選択・次回起動時自動起動・Voice ID取得 | **必須** | 明示されたユーザー操作の簡素化 |
| AutoAdv独自の汎用カスタムPythonルール実行基盤 | 標準機能から除外 | 文字列置換・正規表現・読み辞書・ルビで今回の要件を満たす。独立した実行方式を増やさない |
| 機能別の固定画面数、独立Server Lifecycle Domain | 必須概念にしない | UI・Applicationの構成は利用しやすさと必要な動作で決定する |
| 旧A01～A26の全件維持、追加試験IDの件数維持 | **廃止** | 新しい契約ごとに必要な検証を再選定。旧ケースが必要なくなった場合は削除 |

撤去は安全条件の撤去を意味しない。情報不足時の停止、TTSの実再生完了確認、非同期処理の旧世代失効、入力直前の再検査、1台詞1入力以下、ACK前の再送禁止は維持する。

## 3. Luna原文の取得

1. LunaのHOOK UIでユーザーが正しいHOOKを選択する。HOOK1＝話者、HOOK2＝本文の作品では、両方を選択し、話者→本文の結合順をLunaで設定する。通常の区切りは改行。AutoAdvでは**Lunaが実際に出した原文**をプレビューできるようにする。
2. Lunaの複数HOOK出力は選択順・短い収集時間で結合されるだけで、話者と本文が常に正確にペアになる保証はない。話者が変わったときだけ出力される作品、文字送りで本文が部分更新される作品では、実際の出力を確認する。AutoAdvがHOOK発火時刻、前回話者の推測、HOOK IDの再現から勝手に修復しない。
3. ゲーム由来の制御文字・重複描画・文字化け等の**取得品質**はLunaのゲーム別前処理と`POSTSOLVE`で必要最小限修正する。AutoAdvの話者・本文分離やTTS読み置換に相当する規則をLunaにも重複登録しない。
4. AutoAdvは公開`/api/ws/text/origin`だけを標準入力とする。WebSocketが配信するのはLunaの後処理済み文字列であり、HOOK ID、確定行ID、画面表示完了、ゲームPID、Voiceアセット等のメタデータは保証されない。AutoAdvは接続世代・受信連番・単調時計の観測時刻を自ら付与するが、受信1件を台詞1件とはみなさない。
5. 対象ゲームとLuna原文の対応が確証できない場合は入力を行わない。GUIで現在の対象ゲーム・Luna接続・最新原文を表示する。ゲーム切替・HOOK再選択・WS切断などで確証を失ったときは現在の自動進行処理を失効させ、安全停止する。公開APIでは自動識別できない属性を取得済みと偽らない。
6. **撤去**：`scripts/luna_bridge_patch.py`、`integrations/luna/autoadv_luna_bridge.py`、`autoadv/luna_bridge.py`のUDP候補経路、およびその起動設定・既存パッチに依存した運用。利用中のLunaパッチを元に戻す操作は移行手順として記載するが、旧経路を常設しない。

公開WSが捨てた空イベントを復元しようとしない。独立した正の遷移証拠がある同文連続は処理できるが、判別不能なら追加の行を作らず進行を保留する。「あらゆる空行・同文を再構成すること」は今回の完成条件ではない。

## 4. `Utterance`を中心とした本文解析・読み置換

### 4.1 利便性を優先した共通データ

`Utterance`は**維持する**。現行の話者／本文だけでなく、TTS・ASR・UIに必要な派生結果とVoice割当てまで一度に参照できる構成を積極的に認める。機械的な責務分離のためにDTOを分割したり、画面ごとに再解析させたりしない。

```text
Utterance
  observed_original: str                # Luna受信原文、保持する
  speaker: str | None                  # 解釈できた話者。不明ならNone
  body: str                            # 発話／地の文本体
  structure_rule_id: str | None        # 適用された抽出規則
  content_kind: SPEAKABLE | SYMBOLIC | NON_DIALOGUE
  tts_text: str                        # TTS用の読み置換結果
  asr_target: str                      # native音声照合用
  effective_chars: int                 # 無音閲覧時間等の参照
  tts_route: SELECTED | DEFAULT | SKIP | UNASSIGNED
  voice_id: str | None
  config_revision: str                 # 生成時の設定識別子
```

これは実装の強制的なフィールド名・列挙名ではなく、**共有する利便性と原文保持**を定める契約例。実行時の自然なDTO設計を優先する。`DISABLED`はTTS全体の利用設定、`UNASSIGNED`はルール解決後の割当て不在とし、理由なく独立した話者ポリシーと同格にしない。外部サーバーの起動状態や音声再生中といった変化し続ける情報は、Utteranceを毎回作り直して表現する必要はない。独立した`EMPTY_EVENT`は標準の台詞種別にしない。

| 受信原文の例 | 話者 | 本文 | TTS文の例 |
|---|---|---|---|
| `大和「おはよう」` | 大和 | おはよう | おはよう |
| `大和\n「京(みやこ)、おはよう」` | 大和 | 京(みやこ)、おはよう | みやこ、おはよう |
| `今日は雨だ。` | 不明（作品でナレーションと認定される場合は明示） | 今日は雨だ。 | 今日は雨だ。 |
| `「……」` | 不明 | …… | 発話なし（native音声の有無は別判定） |

### 4.2 作品別の本文分離・読み置換

- GUIで話者・本文の構造ルールを管理する。標準で`話者「本文」`、`話者\n本文`、地の文を扱う。複数行本文を欠落させない。正規表現による名前付き`(speaker)`／`(body)`捕捉、規則の優先順位、ON/OFF、適用条件、ルール競合／不一致のプレビューを用意する。
- 作品固有の文字列置換・正規表現置換、ルビ処理、読み辞書、名前の読み分けを提供する。`京(みやこ)`では元の漢字を二重に読まない。`京`→`みやこ`を`東京`の内部へ機械的に適用しない。`(ため息)`等、単なる括弧を一律ルビとして削除しない。
- 原文は保存し、TTS用・ASR照合用の派生文を分ける。TTS固有の発音・読み方を無条件にnative音声照合へ流用しない。話者名を含むからというだけで本文内の人物名を話者と判定しない。
- 作品別話者に、特定Voice ID・既定Voice・TTS SKIPを割り当てる。未知話者の規定動作を設定できるようにする。**SKIPは読み上げ禁止であり、ゲーム台詞を飛ばす操作ではない**。
- 最新のLuna受信原文をGUIへ取り込み、原文→話者→本文→TTS文→ASR文→Voice割当てを**実処理と同一の結果**として一画面で確認・試聴できるようにする。無効規則は利用者が認識できる形で表示する。
- AutoAdvに汎用Pythonスクリプト実行エンジンを追加しない。通常規則では扱えない具体的ケースが見つかれば、そのケースの利用価値と既存Luna設定での解決可否を評価する。一般的なプラグイン機構を先回りして追加しない。

### 4.3 設定と実行時の一致

作品別の本文分離・置換・Voice割当ては単一の保存形式で持ち、GUI編集、プレビュー、実行に共用する。入力不正・正規表現エラー・存在しないVoice IDは保存／実行前に分かる範囲で表示する。設定の途中編集を現在処理中の台詞に割り込ませず、**保存済みの設定を次の安全な境界から使う**。再起動が必要な変更は稼働中に無断実施しない。

設定の版を追跡する必要はあるが、専用のDraft/Revision管理システムを建てることを要件にしない。既存の設定を安全に保存・反映できる最小の仕組みを採る。

## 5. PySide6 GUI：通常操作と確認の一元化

Python実装を利用し、Windowsアプリは**PySide6／Qt Widgets**を基本とする。起動・停止・作品選択・Irodoriフォルダ指定・本文分離・読み置換・Voice割当て・監視状態・試聴をGUIから操作できるようにする。GUIは実行ロジックを複製せず、同じApplicationサービスが処理した結果を表示する。処理待ちでGUIスレッドをブロックしない。

**常時確認できる情報**：対象ゲーム／フォーカス、Luna接続と最新原文、現在Utterance（話者・本文・TTS文・Voice）、Irodoriフォルダと接続状態、Voice一覧、native/TTS/silentの現在の提示経路、音声監視健全性、進行許可、停止理由、送り済み／遷移待ちの状態。

**主要な操作**：作品の選択・設定、Irodoriフォルダの初回指定／変更、本文分離・読み置換のテストと保存、Voice割当て・試聴、監視開始・終了、自動進行許可／解除、一時停止・安全な再開、必要に応じたサービス再試行。単なる画面数やタブ分割を固定しない。**必要な情報は非表示にせず、無効状態と理由を示す。**

Irodori起動と自動進行の許可は別。GUIでの監視開始・自動進行許可を同じイベントとみなさない。試聴はゲーム用TTSと区別し、試聴完了をControllerの当該台詞の読上げ完了に変換しない。ウィンドウ閉鎖／異常終了後も入力許可が残らない。自動起動を設定したIrodoriは次回も起動するが、自動進行許可を無条件に復元しない。

Windowsで通常のアプリとして起動できる配布・設定保存・ログ・依存ファイル配置と、正常／異常終了時の説明を提供する。ただし配布のためだけに第二のWebサービスやElectron層を新設しない。診断CLIが残る場合は同じApplication機能への入口であり、第二のゲーム送りループにはしない。

## 6. Irodori Server：フォルダ指定後の自動起動とVoice ID

### 6.1 標準動作

1. 初回、GUIで**既にインストールされたIrodori-TTS-Serverのルートフォルダ**を指定する。有効なフォルダを保存したら、**その場で**接続／必要なら起動する。
2. **次回以降はAutoAdvの起動時に毎回**、保存済みフォルダの設定を読み、既存サーバーに接続できれば再利用し、未稼働なら指定フォルダ内の既存Python環境で自動起動する。毎回手動で起動ボタンを押す操作を要求しない。作業ディレクトリは指定ルートにする。
3. 起動経路は公式の`python -m irodori_openai_tts`等、**実在する導入済み仮想環境**を使用する。`uv run --no-sync`を選べる環境なら利用してよいが、アプリ起動を口実に`git clone`、`uv sync`、モデルのダウンロード、依存更新はしない。起動引数は配列として渡し、秘密情報をログに出さない。
4. `IRODORI_VOICES_DIR`（未指定時はルート内`voices`）と、設定済みaliasファイル（未指定時は`voices/voices.json`）を読み取り、Voice ID候補を表示する。サーバー公式の拡張子（WAV、FLAC、MP3、M4A、OGG、OPUS、AAC、WEBM、`.pt`、`.pth`、`.speaker.safetensors`）の直下ファイルとaliasキーを対象にする。`old/`等の子フォルダは走査しない。
5. 接続後に`GET /v1/audio/voices`で実際にサーバーが公開するVoice IDを取得し、**話者割当てUIの選択候補へ自動反映**する。ローカル走査は起動前・障害時のID候補表示と設定診断に使う。サーバーの内部Voice解決器をAutoAdvに作り直さない。ローカルとAPIが異なるときはAPIを使用可能候補の正本とし、差を明示する。
6. 既存の話者設定が指していたVoice IDが一覧から消えても勝手に他の声へ差し替えない。Voice一覧はGUIで更新でき、次回アプリ起動時にも取得する。

**Irodoriの通常利用に手動起動・モデル準備検査・全Voice合成試験を要求しない。** `/health`への応答はAPIへの接続状況を表し、合成成功は実際のTTS要求の結果で判断する。初回モデルロードはサーバー本来の動作に委ねる。AutoAdvはTTS要求失敗・認証エラー・voice未登録・音声再生失敗を、既存TTSエラー処理とGUIの通知で扱う。独立した「モデルロードReady管理Domain」を作らない。

### 6.2 起動したサーバーと既存サーバーの扱い

AutoAdvが起動したプロセスだけ、終了時に停止する。外部から稼働中のIrodoriや接続先を勝手に終了・再起動しない。ポートが別サービスで使用されている、または想定したIrodoriと判断できない場合は重複起動・強制終了せず、理由を表示する。既存サーバーへの接続時は実際のVoice一覧を採用し、選択フォルダと同一であるか分からないものを同一と断定しない。

通常操作は自動接続・自動起動・障害表示・必要時の再試行で足りる。サーバー所有区分は安全な終了のために内部で持つが、専用の多段階Lifecycle状態機械、手動Server管理専用製品、独立Domainへの細分化を要件にしない。正常なGUI終了では自分が起動したサーバーを終了する。異常終了後に残ったプロセスを所有確証なくkillせず、次回は稼働APIの再利用可否を判断する。

Irodoriが起動できなくても、GUI、Luna原文受信、ゲームnative音声監視など**TTSに依存しない動作を無関係に停止しない**。ただしTTS必須設定や実際に当該台詞の提示が不可能な場合は、Controllerの停止・退避条件に従う。外部サーバーのVoiceファイルやaliasをAutoAdvがアップロード・変更・削除する機能は今回追加しない。

## 7. native音声・TTS・無音閲覧・自動進行

### 7.1 音声とTTS

- WindowsのProcess Loopbackで対象ゲームの音声を取得し、AutoAdv/Irodoriの音声出力を混入させない。音声捕捉が失敗しても`native音声なし`と扱わない。
- VAD/ASRを現在のUtteranceの`asr_target`へ照合し、開始・終了を現在行へ帰属させる。単なるVAD無音、ASR一致、任意の固定待機時間を単独の発話終了条件としない。観測は表示途中にも継続する。
- nativeが当該台詞にある場合は原音の終了を待つ。native不在が認められる場合に、割当てがあればIrodori TTS、なければ無音閲覧へ進む。根拠不十分なら進めない。実測で適切に校正された限定的な無音推定と確定情報は区別する。
- TTSのHTTP合成完了と音声デバイスでの実再生完了を区別する。late native onsetではTTS生成・再生を取消し、ゲーム音声の終了待ちへ切り替える。BGM・SEや前行の音声だけで誤って取消・帰属判定しない。
- SKIP、Voice未割当て、Irodori不調を、台詞自体を飛ばす許可と解釈しない。無音閲覧が可能なのは当該台詞のnative不在と表示・画面条件が成立したときだけ。長文は文字数に応じて閲覧時間を確保する。
- 進行中の一時停止、Luna切断、ゲーム切替、Irodori再接続などで既存台詞のTTS/ASR/タイマーを適切に取消し、旧ジョブの完了イベントで次行を送らない。

### 7.2 画面と遷移

AutoAdvのTesseract OCR本文読取、OCRの文字列一致、旧六種類の必須マーカーテンプレートを撤去する。画面観測自体は続け、作品に適した**肯定的な進行可能根拠、選択・操作が必要な状態の禁止根拠、入力後の遷移ACK**を得る。共通契約は「許可／禁止／不明」とその観測根拠で足りる。`CHOICE`、`MAP`、`MENU`等の詳細名は診断表示で使ってよいが、種類ごとの分類器を必須にしない。

「禁止画面が見えない」ことを肯定的な進行許可にしない。原文を受信しただけでは表示完了ではない。独立した境界が確認できない空白・同文連続では新行を推測して送らない。ゲーム固有の正の観測がない場合に、時間経過だけで空イベント・遷移ACKを捏造しない。

### 7.3 選択肢の手動操作からの自動復帰

**通常の選択肢停止は、一時停止と異なる。** 自動進行が許可されていたセッションで選択肢等の手動判断画面を検知したら、入力権限のみ停止し、必要な観測を継続する。ユーザーが選択肢を操作しても、その操作をAutoAdvの自動入力として数えない。旧台詞に結び付くTTS／ASR／タイマーを失効させる。

操作後に、対象ウィンドウが一致し、手動選択画面を離れ、新しい通常台詞・表示完了・ゲーム音声条件・必要な境界証拠が確認できた場合、**ユーザーによる別途のResume操作を必須にせず**自動進行へ復帰する。単なる画面変化、選択肢の消失、Luna受信1回では復帰しない。観測不能なら安全停止して理由を表示する。

一方、ユーザーがGUIで明示的に一時停止した場合、通常のゲーム操作による手動介入、接続断、対象ゲーム切替、障害などでは、自動許可を勝手に復元しない。**「選択肢の通常操作による復帰」と「セッション中断・異常からの復旧」を分けるのは使い勝手と誤送り防止のため**であり、独立した大量の状態分類を作るためではない。

### 7.4 入力の安全契約

進行を決定できるのは単一Controllerのみ。`session_id`、`line_epoch`、`cancel_token`、単調時計の時刻により現在行と非同期結果を照合する。Controllerが進行可能と判断した場合でも、実入力の直前にターゲット窓、表示完了、画面許可、手動入力、native/TTS終了、遷移待ちを再確認する。**自動進行入力は一行につき最大1回**、送出後は観測できる遷移ACKまで再入力しない。未知・不一致なら停止する。

## 8. Application・設定・GUI実装

GUIは操作の入口であり、ゲーム入力やController内部のStateを直接書き換えない。GUIと診断CLIは同じApplication実行経路を使う。GUIが重くならないよう、WebSocket、Process Loopback、ASR、TTS、プロセス起動・終了はGUIスレッド外で処理し、確定した状態をGUIへ通知する。本文解析・置換のプレビューは実行と同一実装を利用する。

- 共通設定：Luna接続先、Irodori Serverフォルダ、保存された自動起動設定、ASRモデル、音声入出力、ログなど。
- 作品別設定：本文分離、読み置換、話者とVoice、TTS利用方針、無音閲覧の時間、ターゲットゲーム・送りキー、表示完了／進行許可の観測方法。
- 設定保存：型検証・不完全保存防止・現在台詞へ途中適用しないことを満たす。GUIとCLIで別スキーマを持たない。旧設定の移行が必要なら一度の明示操作で変換し、旧経路をランタイムに常設しない。
- Irodoriプロセス管理：既存Application側のサービス処理として実装できる。別のDomainを設けることを要件にしない。voice一覧はローカル走査の結果を候補とし、起動後のAPI応答を使用可能な正本とする。
- 完了条件：設定が保存され、AutoAdv再起動でIrodoriが自動接続／起動し、Voiceが選べ、本文ルールがそのまま実行され、自動進行が勝手に有効化されないこと。

## 10. 必須検証・新しい受入条件

旧A01～A26や旧L/U/S/G/Cの番号・件数は受入の目的ではない。**新しい完成動作に不可欠なケースを選定**し、旧テストは契約が一致するものだけ再利用する。必要な検証を「ローカルで環境がない」理由で変更単位から除外せず、Windows実機が要るものは未検証と区別してCI・実機で確かめる。

| 対象 | 受入条件 |
|---|---|
| 原文接続 | Lunaで選択したHOOKの結合結果が公開WSから届く。受信文字列を確定行IDと誤認しない。切断・対象切替では失効する |
| Utterance | `話者「本文」`、`話者\n本文`、複数行、ナレーション、未知話者、記号、ルビで結果が一致し、TTSとASR・GUIが共用できる |

**実機検証**：少なくとも代表作品（『つよきす -Full Edition-』等）で、HOOK1話者／HOOK2本文、ゲーム音声あり／なし、遅延音声、読上げSKIP、記号台詞、選択肢後の自動復帰、手動介入、同文連続の情報不足時停止、Irodori自動起動、Voice選択を確かめる。固定の100行・300～500行などの件数達成をそれ自体の完了条件にしない。誤送り率を報告する場合は独立した正解ラベルと評価対象を示す。

構造化ログは現在のセッション・台詞世代、Utteranceのハッシュ、音声帰属根拠、TTS voice、送出／ACK、停止理由、Irodoriの起動・接続・エラーを含む。音声・画面原データは通常保存を義務づけない。Unit/architecture/integrationテストで状態遷移・キャンセル・GUIと共通処理の一致を検証し、Windows環境でしか成立を確認できない部分は実機未検証として残す。

## 11. 実装とpublish

1. 変更後の完成条件と既存正準の衝突を解消する。`docs/integration-spec.md`は**今回の仕様変更を反映するために**更新し、テスト契約も見直す。
2. 共有Utteranceと本文分離・読み置換・Voice割当てを、既存TTS/ASR経路へ通し、GUIプレビューで同じ結果を使えるようにする。重複解析は新経路成立時に撤去する。
3. Irodoriフォルダ選択・設定保存・アプリ起動時自動起動・Voice ID一覧を接続する。既存TTS worker／再生完了を使用し、起動状態管理を不必要に独立したDomainへ拡張しない。
4. Luna公開WSと、OCRなしの最小画面・入力前ガード・遷移ACKを、既存Controllerへ接続する。旧UDP・OCR関連経路を撤去する。
5. PySide6 GUIで作品設定・話者分離・読み置換・Voice選択・監視・進行許可・選択肢後の自動復帰を一連の通常操作にする。診断CLIの二重制御を整理する。
6. 関連検証とWindows実機評価を行い、運用説明・設定例・配布を完成させる。

各段階は大きな完了待ちではなく、契約や利用経路としてまとまり、既知の不整合がなく検証できた時点でcommit・`develop`へpublishする。`main`の更新・version変更は承認後のみ。通常開発で別ブランチやworktreeを作らない。最新`develop`のFast CI `source-snapshot`からローカルrepoを復元し、`scripts/publish_request.py init`で基点を記録する。以後`prepare`の出力どおりPublish Gatewayを実行し、成功後`record`する。次のpublish前に直前のFast CI結果を確認し、失敗時は規定手順に従って原因を解消する。成立済みローカルcommitをpublish都合でrebase/resetしない。

## 12. 完了判定

- **通常操作が簡単**：GUIでIrodori Serverフォルダを一度指定したら以後は自動起動／接続し、`voices`のVoice IDが話者割当てに現れる。手動Server起動は必要ない。
- **本文処理が使いやすい**：LunaのHOOK選択・結合を利用し、AutoAdvのUtteranceひとつで原文・話者・本文・TTS文・ASR文・Voice IDを共用。GUIプレビューと実行結果が一致する。
- **音声と進行が成立**：native／TTS／silentが交互に発生しても安全に処理し、手動選択後は必要な観測を経て自動復帰する。音声・画面・行境界が不明なら勝手に送らない。
- **不要な旧機能が残らない**：Lunaパッチ・UDP・本文OCR・六種必須校正・Voice Metadata常設Adapter・余分なServer Domain・汎用Pythonルール基盤・旧テスト契約の維持を目的化しない。
- **GUIだけで実用になる**：作品設定、試聴、監視、停止理由、Irodori設定、通常の起動・終了・診断を扱える。CLIや手作業の起動を日常運用の必須条件にしない。

基盤とGUIの静的・自動検証完了と、Windows実ゲームでの連続進行・実音声の成立は分けて報告する。実機未検証をCI greenで完了と表現しない。
