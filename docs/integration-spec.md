# AutoAdv — 製品仕様

## 1. 目的

AutoAdvは、個人利用のWindows GUIアプリとして、次の一連の操作を実現する。

1. **LunaHookからゲームの台詞を取得する。** ゲームに適したHOOKを探して選び、作品別に保存し、次回起動時にも使えるようにする。
2. **必要な台詞をIrodori TTSで補完する。** 原文から話者・本文・読みを求め、話者と作品ごとの設定に従って音声を使い分ける。
3. **ゲームの音声収録状況にかかわらず通常の会話を自動で進める。** 既存音声・TTS・閲覧時間を適切に扱い、プレイヤーが許可した間、台詞の提示に合わせて送り操作を行う。

LunaTranslatorを別途起動して設定を重複管理することなく、複数の作品とプロファイルを継続利用できる。完成の判定は、これらが実際のゲームと日常的なGUI操作で一続きに使えることで行う。

## 2. 通常の操作

### 初回の共通設定

- GUIで既存のIrodori-TTS-Serverフォルダを指定する。既存サーバーへの接続を優先し、必要なら指定された環境をAutoAdv起動時に自動起動する。
- 使用可能なVoice IDを取得し、試聴できる。サーバー・Voiceの状態と問題をGUIで確認できる。
- 音声取得・ASRなどは、選択した動作に必要な場合に設定する。音声監視を使わないTTS運用にASRモデルや音声捕捉環境の準備を必須としない。
- インストール・モデル取得・既存音声素材の加工は利用者が明示的に行う。AutoAdvは外部のインストール環境を勝手に変更しない。

### 作品の設定と使用

1. ゲームを選択・登録し、必要ならAutoAdvから起動する。実行中のゲームは識別情報から候補を提示する。候補が重複する場合は利用者が選ぶ。
2. HOOKを探索し、取得した原文をプレビューして選択する。HOOKコード、取得補正、関連する出力を作品のプロファイルへ保存する。
3. 話者・本文の分離、読み替え、話者別Voice、TTSを使用する台詞と既存音声の扱いを設定する。適用後の文と試聴結果を確認できる。
4. 監視を開始すると本文と適用設定、音声の処理状況が確認できる。自動送りは利用者が別途明示的に許可する。
5. 進行中も一時停止・手動操作・再許可ができる。対象のゲームやプロファイルを切り替えたときは、前の処理が残らない。

接続状態、取得原文、話者・本文、適用Voice、音声処理、進行の許可と停止理由など操作判断に必要な情報は、無効時も状態を示して所定位置に表示する。表示を隠したり入れ替えたりすることを簡素化の手段としない。取得・音声・入力処理でGUIをブロックしない。設定変更は適用時点を明確にし、進行中の台詞を予期せず置き換えない。

## 3. ゲーム台詞の取得

### LunaHook

標準の本文取得源はLunaHookとする。LunaTranslatorが培ってきたエンジン・エミュレーター対応、HOOK探索・追加・選択・復元、取得品質処理を活用する。Native/Hostと関連Python側の有用な資産を、上流版との整合と更新追随の負担を考慮して統合する。

- 候補HOOKのコード、対象プロセス、スレッド/contextなどの識別情報と、受信した原文を関連付けて表示する。手動HOOK追加、保存HOOKの再接続、取得補正を扱う。
- 本文と話者などが複数のHOOKに分かれて出力される作品では、利用者が出力の役割・対応・優先順位を設定できる。対応関係の不明な出力は別の候補として扱う。
- 通知ごとに、取得元、作品・プロファイル、接続世代、受信順序、時刻、利用可能なHOOK情報を保持する。上流処理後の文字列とゲーム内部の生バイトを区別する。
- 文字列の逐次増加、同文の反復、別台詞の同文、空通知、別HOOKの混信を、ゲームの取得特性と設定に従って処理する。更新通知一回を常に台詞一個とみなさず、同文であることだけで別台詞の可能性を排除しない。

### 任意OCR

HOOKで取得できない作品には、利用者が明示的に選択するOCR取得を用意する。初期対応は既にインストール済みのTesseract CLIとし、エンジン・言語・画面領域を作品ごとに保存する。OCR本文は同じ解釈・音声経路へ渡す。OCRの文字誤認や表示変化を踏まえ、取得の安定性と会話送りの設定は実用できる範囲で扱う。HOOKで利用する作品にはOCRの設定を要求しない。

## 4. Utteranceと音声設定

取得原文から、話者、本文、読み上げ文、音声照合文、適用ルール、Voice・音声方針を一つの**Utterance**として解釈する。GUIプレビュー、実際のTTS、音声照合はこの同じ結果を使う。

作品・プロファイル別に、次の設定を提供する。

- 話者名と本文の分離。括弧・引用符・改行・区切り記号、別HOOKにある話者情報、複数規則の優先順位。
- 通常の文字置換・正規表現・読み辞書・ルビの処理。人名と複合語で読みを使い分け、ルビ表現では元の漢字を二重に読まない等の規則。
- 話者・台詞の種類に応じた音声方針とVoice。**既存ゲーム音声を使用する／Irodori TTSを使用する／状況から選択する／読み上げず閲覧時間を使う**という実用的な選択を用意し、未知話者の既定動作も設定する。
- 原文・分離後本文・読み上げ文・使用Voice・音声方針の確認と試聴。

話者別の指定が優先される。例えば、既存音声のある人物は原音を使い、無音声の主人公だけTTSを使い、ナレーションには別Voiceを割り当てられる。利用者がTTSを指定した台詞では、その指定を単なる原音の存在によって打ち消さない。全体のサーバー設定・音声環境は共通設定に持ち、必要な値だけ作品側で上書きする。

## 5. 既存音声・TTS・閲覧の同期

台詞ごとの音声処理は、Utteranceに決定された方針に従う。

- **原音を使う台詞**：対象ゲームの音声をWindows Process Loopbackから取得し、VADおよび必要に応じた日本語ASRで台詞との対応と再生区間を判定する。対応した音声の再生が終わるまで送らない。
- **TTSを使う台詞**：指定されたIrodori Voiceで合成・再生し、生成応答ではなく実際の再生終了を待つ。失敗やキャンセルを利用者に示す。
- **自動選択する台詞**：話者設定、既存音声の照合状況、作品別の待機条件に従い原音とTTSを切り替える。BGM・効果音をその台詞の発話と混同しないようにし、原音が遅れて確認された場合は重複再生を減らすためTTSの取消・切替を行う。
- **読み上げない台詞**：設定された閲覧時間を確保する。

ASRによる音声照合、音声の有無を推測する待機時間、TTSを優先する話者指定などを作品に合わせて調整できる。ASRで台詞音声を確認できない場合の処理は、その作品の音声方針に従う。確認できなかったことを音声が絶対に存在しないという事実とは扱わない。

連続会話において、音声のある人物、ない人物、BGMのある場面、途中から始まる原音が混在しても、音声の重複・途中送り・不必要な停止を抑え、実用的な流れを保つ。本文の取得からTTS再生開始までの遅延も実際の使い勝手として評価し、設定と処理方法を調整できるようにする。

## 6. 会話自動進行

自動送りの権限と現在の台詞の進行状態を、一つの会話進行主体が管理する。HOOK・OCR、音声処理、TTS、GUIはそこへ事実と操作要求を渡し、個別にゲーム入力を送らない。

1. Utteranceを受け取り、設定された音声再生または閲覧を開始する。
2. 対応する再生または閲覧が完了した後、自動送りが許可され、対象ゲーム・ウィンドウ・フォーカス・セッションが有効で、手動介入や未完了音声がなければ送り操作を実行する。
3. **現在の台詞に対して送り操作を一度だけ**送る。入力後は選択HOOK等から次の台詞の処理に進む契機を待つ。
4. 次台詞の判定には、取得元のイベント・順序、本文の更新形態、作品別の取得規則、音声・提示処理の区切りを利用する。同じ文字列の台詞が続く作品も扱えるようにし、単純な文字列差分だけに依存しない。根拠のないタイマー連打はしない。
5. 入力後に取得が止まる、台詞の対応が曖昧になる、ユーザーが手動操作するなどの場合は、状況を表示して操作を利用者へ戻す。本文の取得・読み上げ・設定操作は、送りの停止とは独立して利用できる。

許可操作は、原文を確認してからでも行える。一時停止・再開を日常操作として扱い、実行対象を切り替えた場合は古い候補・TTS処理・タイマー・入力権限を失効させる。入力直前に実際の入力対象と処理中の音声、送信履歴を確認する。マウス移動など通常のGUI利用を誤ってゲームへの介入として扱わない。

選択肢など利用者による判断が必要な場面では、手動停止・選択・再開を行える。HOOK等から場面を識別できる作品では、その情報を停止操作に利用できる。

## 7. 作品・プロファイル・永続設定

AutoAdvを設定の正本とする。

- **共通設定**：Irodori環境・Voice一覧、音声取得/ASR環境、標準音声・待機・入力設定、保存先。
- **ゲーム情報**：表示名とは独立するID、実行ファイルと識別条件、起動方法、既定プロファイル。PID/HWNDは起動ごとに確認する一時情報とする。
- **ゲーム内プロファイル**：HOOK選択・品質設定、任意OCR、Utterance規則、話者・Voice割当て、音声方針、送り設定。作成・複製・改名・削除・切替・既定化をGUIで行える。
- **実行セッション**：接続ゲーム、取得元・音声・入力対象、世代、現在Utterance、再生・進行状態を所有する。

作品識別の不一致・曖昧さはGUIで確認する。HOOK・音声・入力の対象プロセスが作品によって異なる場合には、実際の対象を関連付けられる。既存のAutoAdv・Lunaの設定資産は原本を保全し、利用者が確認して取り込めるようにする。

## 8. 実装・運用条件

LunaHook Native/Hostをゲーム処理と分離して管理し、x86/x64、ABI、実HOOK出力、IPC切断と再接続を確認する。上流の採用版と取り込み手順を記録し、関連するNative・Host・Python資産の版を整合させる。権限や競合等の問題は利用者へ通知し、他アプリのプロセス・環境を勝手に終了・変更しない。Luna由来コードと依存物について必要なライセンス・権利表示に対応する。

入力と音声処理に必要な状態所有、イベントの適用順、ゲーム・プロファイル切替時の失効を一貫した構造にする。Domainから保存・Application・GUIまで同じ設定と状態が使われるよう接続する。

## 9. 受入条件

| 実際の利用 | 完成の判断 |
|---|---|
| 初めて遊ぶゲーム | AutoAdvのGUIでHOOKを探索・原文を確認・選択して利用を開始できる |
| 登録済みゲーム | 識別・HOOK・本文規則・Voiceが復元され、通常は再設定なしで利用できる |
| 話者が分かれた台詞・特殊な表記 | 作品別のHOOK・話者分離・読み規則に従った本文とVoiceが使われる |
| 原音を使う話者 | 対応した既存音声の終了を待って会話を送る |
| TTSを指定した話者 | 原音の有無とは別に指定Voiceで読み上げ、再生完了後に会話を送る |
| 自動選択・混在台詞 | 設定と観測に従って原音とTTSを使い分け、無音声の台詞も進行できる |
| ASRを使わない運用 | 必要な設定だけでTTSまたは閲覧時間による進行を利用できる |
| 連続会話・同文の別台詞・部分更新 | 台詞に対応して送り、二重入力と台詞飛ばしを抑えながら進行できる |
| 手動停止・ゲーム切替 | 操作が直ちに反映され、以前の台詞の音声・入力が復活しない |
| 複数作品・プロファイル | 切替・保存・復元がGUIから一貫してできる |
| 任意OCR | 明示的な選択で本文取得と音声処理に利用できる |

単体・結合テストでは、取得元と世代、Utteranceの一致、音声方針、TTS実再生、入力の一元化と重複防止、設定保存・復元を確認する。Windows CIではNativeのx86/x64と主要Adapter・GUIを検証する。さらに実ゲームでHOOK受信から話者処理、原音・TTS、会話送り、停止・再開まで確認し、実際に成立した範囲を明示する。
